# Contributing

Start with `npm ci`, `npm run check`, `npm test`, and `npm run demo`. The public demo must remain credential-free and must label simulated audio clearly.

For Python recovery changes, follow `docs/setup.md` and run `tests/test-edge-tts-retries.py` using the configured interpreter. Test failure boundaries without repeatedly calling real providers. Do not change live Notion data during CI.

Keep queue ordering and stop-on-failure behavior explicit. Supply a source for factual research findings. Do not turn the ranking heuristic into a claim of predicted performance. Label new features separately from historical production milestones.

Before submitting, run `npm run audit:source` and inspect the actual diff for secrets or personal data. Add tests for changes to shared contracts, queue behavior, or provider recovery. Use issues to explain the problem and proposed behavior before large changes.
